# Hardware test plan: ELM327 over BLE (vLinker MC+)

Settles L10, L11 and L12 in `planning/tasks.md` and the acceptance list of
`planning/tickets/0002-elm327-ble.md`. Cases 4–6 need the drive session (ticket 0001). Run in
order; each case starts where the previous one ended. Never commit captures: they hold vehicle
data, device addresses and, in raw OBD answers, possibly the VIN.

## Preconditions

- [ ] Vgate vLinker MC+ (BLE). Ideally a second, different BLE adapter (case 1 fallback layout).
- [ ] A car with a profile in the picker (EV6 for case 5) and one without (Generic).
- [ ] For case 5: a WiCAN Pro on the same car, paired as a WiCAN, logger on.
- [ ] Vendor app (vLinker) and other OBD apps force-stopped: the adapter serves one client.
- [ ] Android 12+ phone, debug APK, `adb logcat` for lines outside the app log.
- [ ] A multimeter or the car's own 12 V reading (case 2).

**Capture** = Status → Save log (diagnostics export), plus the named screen text or log line. The
first link to an adapter logs `<instant> I link: ELM327 GATT layout: service …, notify …, write …,
bonded …, mtu …`.

## 1. Pair and discover the layout

- [ ] Car on (ignition), adapter plugged in. Pair → OBD-II scanner (ELM327); keep Generic.
- [ ] Note the adapter's name in the CDM chooser. Expected to match `vLinker`; an unnamed entry means it was found by service.
- [ ] No passkey dialog; the wizard goes straight to Test. Test connection.
- [ ] `link:` line: service `0000fff0-…` with notify `…fff1` and write `…fff2` (or which other); `bonded false`; `mtu` 517 or what the adapter granted.
- [ ] Forget, re-pair: same layout line. Test again without forgetting: no second `link:` line (the stored layout is used).
- [ ] Second adapter, if any: its layout line; a fallback pick shows a service outside the candidate list.
- [ ] A WiCAN in range: it is listed in the chooser too (expected).
- Capture: chooser screenshot (crop the address), the `link:` lines.
- Settles: L12 vLinker MC+ layout, name pattern, MTU, no bonding needed.
- If it fails: `Elm327Gatt.kt` (`CANDIDATES`, `NAME_PATTERN`), `GattLayout.kt` (`GattDiscovery.choose`), `KableLinkFactory.kt`, `KableGattLink.kt`.

## 2. Probe

- [ ] Test step shows `<version>, battery <V> V`. Note the version verbatim (`ELM327 v2.2` expected).
- [ ] Voltage within 0.3 V of the multimeter / car reading, engine off and running.
- [ ] Note how long the test takes from tap to result (ATZ resets the chip).
- [ ] Ignition off, adapter still powered: Test again; version and voltage still answer.
- Capture: the test-step text for each, timings.
- Settles: L10 ATZ timing and answer format of `ATZ`/`ATRV` on this adapter.
- If it fails: `Elm327Support.kt` (probe), `Elm327Transport.kt` (prompt, 5 s timeout).

## 3. Bonded layout (WiCAN's ELM327 service)

- [ ] Pair the WiCAN as OBD-II scanner (ELM327); in the chooser pick the `WiC_…` entry.
- [ ] `link:` line shows service `0000fee0-…`, `bonded true`; Android shows its pairing dialog during the test, passkey accepted, test passes.
- [ ] Forget it afterwards (it stays paired as a WiCAN separately if it was).
- Capture: `link:` line, whether the dialog appeared.
- Settles: L12 bonding on first access for a bonded layout.
- If it fails: `Elm327Gatt.kt` (`FEE0` entry), `Elm327Support.kt` (`profile`).

## 4. Car on: rows every poll

- [ ] Re-pair the vLinker with the car's profile (EV6). Start a drive (session per ticket 0001).
- [ ] Status shows the row count growing about every 2 s; the store listing has `elm327/<start ms>` files.
- [ ] Rows: `autopid.*` names from the profile, `elm327.voltage` per round, one `elm327.adapter` with the case 2 version.
- [ ] Repeat with Generic on a car without a profile: standard mode-01 names (RPM, speed, coolant).
- Capture: row counts per param for a minute, the session lines.
- Settles: ticket 0002 acceptance "rows every poll"; L10 answer format, multi-frame decode on real frames.
- If it fails: `Elm327Source.kt`, `Elm327Response.kt`, `ByteExpression.kt`.

## 5. Same drive, vLinker vs WiCAN

- [ ] EV6, both adapters in the car (two OBD ports via a splitter, or one drive each on a fixed route if not).
- [ ] At the sink: the same `autopid.*` names from both sources (`elm327:<address>`, `wican:<address>`).
- [ ] SOC, `HV_AH_*` and `KWH_*` counters agree at the same minute; counters only grow.
- Capture: per-param min/max/last from each source for the drive (no timestamps beyond minutes).
- Settles: ticket 0002 acceptance "same names a WiCAN would write"; the EV6 byte indexes on a real car.
- If it fails: `Elm327Source.kt` (names), the profile in `vehicle_profiles.json` (bytes).

## 6. Car off and adapter sleep

- [ ] End the drive, lock the car. Every PID answers a status line; rounds emit nothing; the session ends by the idle rule.
- [ ] Leave the car parked 1 h; note whether the adapter still advertises (scan with any BLE app) and whether a manual Test connects.
- [ ] Next morning: Test connection; note time to connect and whether the adapter needed a wake (ignition) first.
- Capture: session end line, advertising yes/no after 1 h and next morning, test results.
- Settles: ticket 0002 acceptance "car off"; known gap "adapter sleep".
- If it fails: drive session (ticket 0001), `Elm327Source.kt` (empty rounds).
